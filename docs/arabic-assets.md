# Arabic visual assets

- `public/assets/arabic/dubai-skyline.jpg`: Dubai photograph downloaded from [Unsplash image endpoint](https://images.unsplash.com/photo-1512453979798-5ea266f8880c?auto=format&fit=crop&w=1400&q=85) on 29 October 2026. Used as a city illustration, not a photograph of the company, office or client work. Responsive WebP derivatives at widths 384, 640 and 1080 were prepared using the project’s Next Image optimizer at quality 70. The HTML image selects the right local file directly, with a reserved frame and high fetch priority; no image transformation occurs on the Arabic homepage request.
- `public/assets/arabic/fonts/plex-*.woff2`: IBM Plex Sans Arabic regular, medium, semibold and bold, obtained through Google Fonts and losslessly converted from TTF to WOFF2 with fontTools. Fonts are hosted locally; no runtime Google Fonts requests. License retained in `fonts/OFL.txt`.
- Editorial covers, icons, brand lettering and decorative travel elements are code-native SVG/CSS authored for this section. No stock portraits, fictitious clients, endorsements or generated staff photographs.

The Arabic brand lockup is a typographic treatment of the existing Business Setup UAE name, not a claim of a registered new logo. Motion uses brief `transform`/`opacity` animations and respects `prefers-reduced-motion`. The article and navigation content remains rendered on the server when JavaScript is disabled.


The production Arabic layout uses `uae-arabic-400/500/600.woff2`, subsets derived from the supplied IBM files. The derived family was renamed **UAE Arabic** to respect the reserved name Plex. Original copyright/license notices, `OFL.txt` and original source files remain unchanged. Regenerate with `scripts/prepare-arabic-fonts.py` (fontTools+brotli; not part of the Node deployment build). The unused700 font is not preloaded in the main layout. Fonts use explicit local preloads and `@font-face` with `font-display:swap`; no third-party font requests are required.

On31 October2026 the subset was narrowed from the entire Arabic block to a stable repertoire for standard Arabic content and Egyptian names, rather than only characters currently present in articles. It retains Arabic punctuation U+0600–U+061F, standard letters U+0621–U+063A and U+0640–U+064A, diacritics U+064B–U+065F, Arabic-Indic digits and separators U+0660–U+066D, dagger-alef/alef-wasla U+0670–U+0671, Eastern Arabic-Indic digits U+06F0–U+06F9, and the common borrowed-letter allowlist پچژڤگ (U+067E/U+0686/U+0698/U+06A4/U+06AF). All five borrowed letters are supported by the original and generated fonts. Extended Latin U+0020–U+024F, general punctuation, currency, arrows and common symbols retain their previous coverage.

Exact generated asset sizes are40,000 bytes (400),42,008 bytes (500) and42,312 bytes (600): **124,320 bytes total**, down from154,408 bytes, saving30,088 bytes (19.5%). This preserves extended Latin rather than trimming it for a marginal additional saving. The script retains the original font timestamps for reproducible generation.

Coverage checks found no missing previously supported codepoints used by `app/ar` or `components/arabic`, and no advance-width changes for retained characters. Vertical font metrics match the originals. GSUB, GPOS and GDEF are retained, including initial/medial/final substitutions, required ligatures and mark positioning; `layout_features=['*']` lets fontTools preserve the associated substitution closure. Evidence is in `output/security/font-subset-preview-v2/adopted-coverage-report.json`. Table/coverage checks are not full shaping proof: browser verification of connected Arabic text, lam-alef, diacritics and mixed-script/digit examples remains part of the parent task's final QA. Future Persian/Urdu or Quranic content outside this repertoire requires a coverage review or wider subset. Unsupported scripts use the declared fallback fonts.
